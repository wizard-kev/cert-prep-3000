# Kevin's Super Cert Prep 3000

Local web app for certification exam practice. Each certification has objective files, a reviewed question pool built against them, and exam facts (`cert.json`); CCST Cybersecurity (100-160) ships pre-built. Questions are written with Claude (in a chat or a Claude Code session) and imported; the app runs no AI model and makes no network calls.

**v2 in progress:** `Project Documents/v2_Scope_and_Plan.md` is the governing plan; read it before changing anything and follow its phase order (its section 15 logs what has landed). `Project Documents/CCST_Project_Scope_and_Plan.md` is the v1 (CCST-only) history and CCST content decisions; `CCST_Project_Instructions.md` holds the tutoring rules; `CCST_Official_Blueprint.md` holds Cisco's official topics.

## Map
- `data/certs/<cert-id>/`: one folder per certification (id matches `^[a-z0-9][a-z0-9-]{1,31}$`).
  - `cert.json`: name, exam facts with confidence labels (minutes, question count, passing score, formats), domains and weights, sections (code, name, domain). Validated by `certs.Cert` (unknown fields rejected).
  - `objectives/<CODE>.md`: one objective table per section (codes like `C01`, `^[A-Z]{1,3}\d{2}$`): `| ID | Objective | Core idea | Discriminator |`, plus an optional fifth `Ref` column for the vendor's reference number (e.g. `4.2`), which Focus matches on. Objective IDs `<CODE>-NN` are frozen within a certification: never rename, retire instead.
  - `questions/<CODE>.json`: the section's pool; question IDs `Q-<CODE>-NNNN`.
  - `imports/`: archived question files that were imported (CCST's authored sets live here).
- `data/drafts/<id>.json`: certification set-ups in progress in the wizard (gitignored); deleted when the learner finishes.
- `data/progress.db`: sessions and attempts for every certification (gitignored). `data/backups/`: automatic backups (gitignored); the v1 `tracker.db` was moved here when it was migrated (2026-10-27).
- `src/certprep/certs.py`: certification registry; ids and section codes are pattern-checked and must exist on disk before they touch a path.
- `src/certprep/objectives.py`: section objective files and table parser.
- `src/certprep/schema.py`: question schema (plan 8.3).
- `src/certprep/generator.py`: question import, automated checks (plan 10.2) and surface-cue checks, option shuffle; `targets_for` assigns each chosen objective the angles it has used least (retired questions count, so a replacement takes a new approach).
- `src/certprep/prompts.py`: prompts for a Claude chat (questions, repair, study session, ask about a question); `RULES` mirrors the import checks, `PROMPT_ANGLES` the angles offered. Reply format `certprep-questions` version 1.
- `src/certprep/importer.py`: imports a pasted reply: envelope and field checks (unknown fields rejected), `clean_text` on every text field, per-question checks via `generator.import_items`, a dry run of the full checks on early rejects, a repair prompt for anything rejected, and an archive copy in the certification's `imports/` (`claude-<time>-<hash>.json`).
- `src/certprep/pool.py`: per-section pools, atomic writes; question statuses (plan section 6): `mark_seen` (Unreviewed -> Passively-Validated on first answer), `validate` ("Looks right"), `dispute` / `confirm_dispute` (retires with `Reported by user`) / `undo_dispute`, `retire`.
- `src/certprep/tracker.py`: `progress.db` (schema version in `meta`; schema 2 = confidence 1-5 and `held_disputes` for exam reports), v1 migration, upgrades of older schemas after a `progress-upgrade-*` backup, `backup(reason)` (keeps 10 per reason); `list_backups` / `restore` (reached only through the server's own listing; the backup is read into memory, the current progress saved as `progress-before-restore-*`, an older schema upgraded on the way in). Objective status derived from attempts (plan 8.4); `ObjectiveStats.add` folds in one answer at a time, and `score` (0-100) is the recency-weighted average of `answer_score` (`SCORE_DECAY`).
- `src/certprep/focus.py`: Focus mode (v2 plan 7.2). Pasted text is cleaned and capped (8,000 characters, 60 lines, 300 per line), split into lines without list markers, then matched: objective IDs exactly; reference numbers against the `Ref` column (domain headings like `1.0` are skipped); otherwise word overlap (rare words count more, crude stemming, acronyms the objectives write in capitals), topic by topic for "heading: a, b, c" lines. Results carry only IDs, names and question counts (SR-7). `sessions.select_focus` serves only the chosen objectives, weakest first.
- `src/certprep/wizard.py`: the certification wizard (v2 plan 3.3). Drafts; the exam-facts prompt and reply (`certprep-exam-facts` v1) with per-fact confidence; the objective-builder prompt (the pasted official list is fenced in as data) and reply (`certprep-objectives` v1: sections D01..., objectives with core idea, discriminator, group and Ref); every reply field checked, problems returned with a repair prompt; `install` validates the whole `cert.json`, writes the folder under a hidden `.installing-*` name, renames it into place and reads the objective files back.
- `src/certprep/packs.py`: certification packs (v2 plan 9, SR-5). The export zip holds `manifest.json` (SHA-256 per file), `cert.json`, objective files and served questions, plus retired ones on request. Passive status and first-seen times are dropped, and disputed questions are left out. Import checks the whole zip in memory first: 20 MB, 2,000 entries, fixed name patterns, no links, encryption or duplicates, per-file size caps, 100:1 ratio cap, manifest hashes, strict UTF-8, `cert.json` and question schemas, clean objective cells. Then `certs.install` writes it as a NEW id; nothing is ever overwritten. The upload route `/api/packs/import` is the one POST that takes `application/zip` (20 MB); the token and origin checks still apply.
- `src/certprep/audit.py`: `coverage` (at least 2 questions on 2 angles per objective) and `audit`/`bands` (surface cues), used by the CLI and the in-app question-bank health page.
- `src/certprep/history.py`: progress over time (v2 plan 8.3): totals, scores by section and domain, calibration, status counts after each session, one objective's history; `recommendations` (V11): Weak after 3+ answers, too easy (latest 3 correct at Certain), every question seen.
- `src/certprep/sessions.py`: Practice selection (weak first, missed questions again after 1/3/7 days, a share of untried objectives) and Exam selection (unseen first, by `cert.json` weights); reports with all / validated-only / new / repeat scores and the pass mark; export summary.
- `src/certprep/main.py`: FastAPI routes (`/api/certs/{cert}/...`; sessions at `/api/sessions/{id}`); `/` serves `static/index.html` with this launch's CSRF token filled in; on startup (and after a restore), marks answered Unreviewed questions Passively-Validated. `static/`: UI; `static/charts.js` draws the progress charts as SVG (DOM calls only) and loads before `app.js`.
- `src/certprep/security.py`: middleware run before every route (Host allowlist; Origin + CSRF token on POST; JSON-only, 1 MB body cap; CSP and other headers on every response) and `clean_text` for any free text from the user.
- `src/certprep/launch.py`: starts the app on 127.0.0.1 (`CERTPREP_PORT`, default 8000) and opens the browser; reuses a running instance.
- `tests/`: pytest; `conftest.py` points `CERTPREP_DATA_DIR` at a temp dir holding a copy of the CCST `cert.json` and objectives with empty pools, so tests never touch real data.
- First-start dialog: shown once per browser when no certification has answers and no set-up is in progress (`certprep.welcomed` in localStorage). To see it, use the `certprep-uitest-fresh` launch config (port 8003, a scratch folder holding only `certs/ccst-cyber`).
- UI testing: run the `certprep-uitest` launch config, whose `CERTPREP_DATA_DIR` points at a scratch copy of `data/` (certs plus a copy of `progress.db`), never the real progress. The `certprep-dev` config runs on the real data with reload: while it runs, saving a change to the progress schema or the startup sync applies it to the real files at once. Stop it before such changes and verify them on a copy first.

## Commands
- Install / repair: `install\install.cmd` (idempotent: finds Python 3.12+, builds `.venv` from `requirements.txt`, removes obsolete model settings and renames `CCST_*` settings in `.env`, adds desktop and Start-menu shortcuts, starts the app; `-Port`, `-NoShortcuts`, `-NoStart`). Uninstall: `install\uninstall.cmd` (stops the app, removes shortcuts and `.venv`; keeps progress and certifications unless `-RemoveProgress`).
- Run: `.\run.ps1` or the desktop shortcut (http://127.0.0.1:8000; `-NoBrowser`). Development: `pip install -r requirements-dev.txt` into `.venv`; the `certprep-dev` launch config runs uvicorn with reload on port 8001 against the real data.
- CLI (set `PYTHONPATH=src`; `--cert` defaults to the only installed certification):
  - Import authored questions: `.\.venv\Scripts\python.exe -m certprep.cli import --section C01 --file <file.json> --model <model-id> [--dry-run]`
  - `coverage [--sections C01 C02]`, `audit [--sections ...]`, `retire --section C01 --reason "..." (--ids ... | --all-active) [--superseded]`
- Tests: `.\.venv\Scripts\python.exe -m pytest -q`; installer library: `powershell -ExecutionPolicy Bypass -File tests\test_install_lib.ps1`

- Commit one logical change at a time; never commit progress databases or `.env`.

## Adding a certification
- In the app: "Add a certification" (top bar), or "Something else" in the first-start dialog. The wizard steps are name → exam facts (prompt, paste reply, check and correct) → objectives (paste the official list, prompt, paste reply, check) → Create → first questions in batches until each objective has two → Finish. It can be left and resumed from home.
- Packs: export on home (Question pool > Export this certification as a pack); import with "Add a certification" > "Import a certification pack instead", or from the first-start dialog. CCST's objective files derive from a study guide, so its pack is for personal use only.
- A certification's objective IDs are fixed once it is created. If the objectives were wrong, retire and add objectives by hand, or delete the folder and set it up again before any answers exist.

## Adding questions
- **In the app (the normal way, v2 P4):** home page > "Open the Claude workspace": choose objectives (quick picks: fewer than 2 questions, weak), build the question prompt, paste it into claude.ai, paste the reply back under "Import". Rejected questions come back with reasons and a repair prompt. The rules Claude is given are `prompts.RULES`; keep them in step with the checks in `generator.py`.
- **By hand or in a Claude Code session:** write `{"questions": [...]}` files using the GeneratedQuestion fields (CCST's are in `data/certs/ccst-cyber/imports/`, e.g. `ch01_v2_set1a.json`) and use the CLI import. The rules below apply either way.

## Authoring rules (v2 format since 2026-10-21)
- One question per objective as primary (`objectives[0]`); add look-alike IDs as secondary. Two sets, a different angle per objective in each.
- Every option has a `role`: `best` (keyed answer), `partial` (technically correct, not best), `related` (neighbouring concept/protocol/practice), `wrong` (plausible misconception). Use one of each where it fits. A `partial` option requires a BEST/FIRST/MOST qualifier in the stem.
- No surface cues: options of similar length and form; no absolutes (always, never, only, all, every...) in wrong options unless the answer has one too; the answer must not repeat the stem's wording; no joke options. The import rejects violations.
- Spread answer lengths across the pool: the answer should be the longest option about a quarter of the time and the shortest about a quarter (`audit` enforces bands).
- Describe situations instead of naming the concept in the stem; avoid "which is NOT". Use `exhibit` (log, config, command output, max 30 lines) where it fits.
- About 20-25% multi-select (5 options, 2 answers, stem ends "(Choose two.)"). Difficulty: 1 recall in context, 2 apply to a scenario, 3 best-of-valid or two-step.
- Name the objective's key term somewhere in the question (the explanation counts).
- Don't refer to option letters in rationales or the explanation; options are shuffled.
- Use only the section's own objective IDs, at most 3 per question. Never use specific-looking CVE IDs.
- Run `--dry-run` before importing; after importing run `coverage --sections <CODE>` and `audit --sections <CODE>` (both must pass).
- Replacing a pool: `python -m certprep.cli retire --section <CODE> --all-active --superseded --reason "..."`, then import. `--superseded` keeps the learner's answers counting; without it (reported or flawed questions) their answers are dropped from objective status.
- Reported questions are Disputed (out of play) until the learner confirms the report, which retires them, or undoes it. After a confirmation, check `coverage` (or the workspace's "Fewer than 2 questions" pick) and write replacements on a different angle (the prompt builder does this automatically). Q-C09-0100 (reported 2026-10-22) was replaced by Q-C09-0154 through the in-app flow on 2026-10-27.

## Rules
- The browser sends only certification ids, section codes, question and session IDs, option keys, fixed choices, and short notes, plus three kinds of pasted text: Claude's replies (imports), a Focus list, and the wizard's name fields and official objective list. Ids are pattern-checked and must exist in the registry. Pasted text never goes into a prompt, except in the wizard, where the learner pastes it on purpose for that prompt (v2 plan 5.1). There it is cleaned, capped, and fenced off as data.
- Security baseline (v2 SR-1 to SR-4, `security.py`): every new route is covered by the middleware automatically; any new free-text field goes through `security.clean_text` with a length cap; never use user text in paths, SQL strings, regexes, or shell. Tests and API clients must send `Host: 127.0.0.1`/`localhost`, plus `Origin` and `X-CSRF-Token` on POSTs (see the test fixtures).
- Treat model output as untrusted: validate, and render with `textContent` only (SR7). The CSP forbids inline scripts, inline styles, and `eval`; `tests/test_security.py` fails if the UI builds HTML from strings. Position things from JS with `element.style.x = ...` (CSSOM is allowed), never a `style` attribute.
- Charts: one series per chart, in `--series-1` (validated with the dataviz palette validator for light and dark). Meaning is never carried by color alone: status counts are small multiples named by their titles. Every chart has a table view and keyboard-readable values. If chart colors change, run the validator again (`python -I -X utf8 <dataviz skill>/scripts/validate_palette.py "<hexes>" --mode light|dark --surface <card color>`).
- `style.css` makes `[hidden]` always win over a class's `display`; the UI relies on it to show and hide elements.
- The Help page (`v-help` in `index.html`) describes how things work: statuses, levels, the score formula, revisit and retry intervals. Change it whenever those rules change. "?" buttons (`class="help-link" data-help="<topic>"`) open it at a topic.
- Imported questions enter the pool as `unreviewed`. Unreviewed, Passively-Validated (`passive`) and Validated questions are served in every mode; Disputed and Retired are never served and are left out of scores (v2 plan section 6). Legacy `draft`/`verified` values load as `unreviewed`/`validated`. Retire, never edit in place.
- Never use real exam questions (brain dumps).
- No API keys in code or the browser; `.env` is gitignored.
